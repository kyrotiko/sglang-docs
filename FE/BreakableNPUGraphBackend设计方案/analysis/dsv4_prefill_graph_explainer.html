dsv4_prefill_graph.py 在干什么

一句话：把 DSV4 attention 的 metadata 做成“形状冻结、内容原地刷新”的固定缓冲区，让 breakable prefill graph 在每次 replay 时还能读到新数据。

337 行 1 个类 Dsv4PrefillGraphMetadata 3 个 copy helper + 1 个容量函数 只服务 breakable prefill graph
00

矛盾：capture 冻结的是地址，不是数据

先理解这一点，后面全是它的推论。

eager 路径每步新建

step 1 · fm.positions_cmp_padding_c40x7f10_a000
step 2 · fm.positions_cmp_padding_c40x7f20_c800
每一步都重新分配 tensor，kernel 拿到的是本步的入参 → 永远读到新数据。

prefill graph地址冻结

图里 kernel 绑定的地址0x7f10_a000
本步 Python 新建的 tensor0x7f10_a000
capture 时两者是同一块内存，图读它没问题。
看看 replay 时会发生什么
所以这个文件的核心不是“建新的”，而是“原地写”。 capture 之前把 buffer 按上界一次性分配好、绑定给 kernel；之后每次 replay 只做 copy_。模块开头那句 Nothing in this module may replace a tensor object after capture 就是这个意思。

点每一步，看它负责哪些 buffer、executive 细节是什么。

02

三种 copy 语义：为什么尾巴要清零 / 重复 / 报错

replay 只做拷贝，但“多余的位置”必须仍然是合法值。

_copy_1d(dst, src)

live 前缀清零尾巴
用于 5 个标量向量和 positions / locs。src=None 时整段清零（capture 的 locs 就是这种情况）。 尾巴必须是 0：compressor 的 padding 行会照着零位置去算，不能留下一步的旧值。

_copy_cu(dst, src)

count = 1重复最后一个值
用于 actual_q / actual_q_pa 这类 cu_seqlens。多出来的请求槽必须描述“零长度请求”， 不能复制 request 0 —— 否则会把第一个请求的 token 再算一遍。

_copy_table(dst, src)

用于 3 张 page table。先把整表清零，再拷左上角；live 比 captured 大直接 RuntimeError。 这是整个文件里唯一会主动报“容量算小了”的地方。
共同点：live 之外的位置必须是“合法但无意义”的值。 因为图是整段执行的 —— 多出来的行不会因为数据无效就停下来。
03

compress_capacity：压缩行的容量上界

这个 buffer 同时也是 compressor 算子的行轴，所以不能小、也不能随便大。
每 ratio 个 token 产出一条压缩行；一个 chunk 起点不对齐时，最多比 ⌊chunk/r⌋ 多出 1 行（跨块）。max_reqs=1 时这个余量就是 +1。
完整块 ⌊T/r⌋256
边界余量 +B+1
容量 C_cap(r)257

取 min(T, …) 是因为行数不可能超过输入 token 数；bs 接近 T（大量 1-token 请求）时第一项会算松。

为什么“+1”：一个完整的例子

bucket T = 32，ratio = 4，一个请求：prefix = 3，本 chunk = 29。

0prefix 3（灰）chunk 29（青）32
压缩行：8 行最后一行跨块 → 高亮
⌊32/4⌋ − ⌊3/4⌋ = 8 行；而 ⌊29/4⌋ = 7。差值 1 就是起点不对齐的代价。 容量公式用 t = chunk = 29 算：min(29, 29//4 + 1) = 8，正好等于真实行数 —— 上界是紧的。
04

为什么要 stage_topk：eager 断点要按层取 buffer

indexer 在图里，attention 留在断点；共享属性只记得最后一层。

capture 时每一层的 indexer 都在图内分配自己的输出张量（存储属于 graph pool）。attention 被切在 eager 断点， replay 之后才执行。如果只写共享属性 fm.c4_topk_indices，它只能记住最后一次赋值（layer 号最大的那层）。

stage_topk(layer_id, tensor) 在 capture 时按层存引用；replay 时断点按层号取回自己那块 buffer。 dict 只存引用，不占额外显存，也不需要 refresh。

05

它对外只暴露 3 个入口 + 1 个硬约束

入口

  • allocate() ← capture hook init_forward_metadata_for_breakable_cuda_graph_capture
  • refresh() ← replay hook prepare_forward_metadata_for_breakable_cuda_graph_replay
  • stage_topk() ← indexer 的 _forward_indexer

backend 通过 use_captured_forward_metadata_for_breakable_cuda_graph 打开这套路径，并把 prefill_cuda_graph_max_batch_size 设为 MAX_PREFILL_GRAPH_REQS。

硬约束MAX_PREFILL_GRAPH_REQS = 1

一次 replay 只接一个请求。多请求需要 fused indexer / sparse-attention 的 metadata 算子支持零长度请求槽， 目前未验证 —— 所以超过 1 个请求的 batch 直接走 eager。

这也解释了为什么 _copy_cu 的尾巴是“重复最后一个值”：那是第 2、3… 个槽位的零长度请求语义。
