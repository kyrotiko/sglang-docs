总览

两条路径：V4 的 C4/C128，V4.1 的 C1/C2

同样是压缩 KV，但压缩比、池的数量、indexer 的参与方式都不同。

// 两条路径的分界，不是模型层数，而是“池的类别” V4 : SWA / C4 / C128 → 各自的 entry，item_bytes 取 page_bytes V4.1 : SWA → 普通 entry : C1 / C2 → low-ratio entries（KV + indexer K/scale）
low-ratio 是什么

一个 full page，在 C1/C2 里有多少个槽？

full page 固定 128 token；压缩比决定它在某个池里的槽数 S。

Full page128 tokens · 0..127
C1 · ratio 1S = 128
C2 · ratio 2S = 64
// low-ratio 路径的输入 S = page_size / ratio → C1: 128 / 1 = 128 C2: 128 / 2 = 64 row_bytes → C1/C2 KV: 320 B；indexer K: 64 B；scale: 4 B item_bytes = S * row_bytes
indexer

indexer 的 native page 不是 full page

KV 的 S 和 indexer 的 K 不是一回事；一个 full page 要覆盖 I = S / K 个 native index page。

C1 indexer · I = 2

S=128, K=64 → 两个 native page 折成一个 full page。

fold I=2 →
C1 indexer K: 128 × 64 = 8192 B C1 indexer scale: 128 × 4 = 512 B

C2 indexer · I = 1

S=64, K=64 → 一个 native page 就是一个 full page。

I=1 →
C2 indexer K: 64 × 64 = 4096 B C2 indexer scale: 64 × 4 = 256 B
// 为什么需要 reshape：indexer 的设备页是 K 槽，不是一个 full page I = S / K → C1: 128/64 = 2 C2: 64/64 = 1 item_bytes = I × native_page_bytes device buffer : [full_pages*I, K, 1, dim] → [full_pages, S, 1, dim]
布局

GPU 是 2-D 行，NPU 是 4-D PA_ND

同一份 KV，GPU 按字节行存；NPU 的 sparse attention 算子按 (pages, kernel_page_size, 1, dim) 读。

GPU · 2-D
[pages, native_page_bytes]
page 0
page 1
page 2
view(uint8).reshape(full_pages, -1)
NPU · 4-D PA_ND
[pages, K, 1, dim]
page 0 · K slots
page 1 · K slots
page 2 · K slots
page.reshape(full_pages, S, *page.shape[2:])
// 旧代码的坑：4-D 上 shape[1] 是槽数，不是字节数 buffers[0].shape = [pages, S, 1, dim] shape[1] * itemsize = S * itemsize ≠ S * row_bytes = full page 字节 正确：buffers[0][0].numel() * element_size()
为什么 V4 没事

V4 也走 4-D，但它从来没有用 shape[1] 算 item_bytes

问题不在“4-D”，而在 V4.1 low-ratio 路径手写了一个只对 2-D 成立的公式。

DSV4（V4）

SWA / C4 / C128 entry 统一用 buffer info：

item_bytes=swa_info.page_bytes item_bytes=c4_info.page_bytes item_bytes=c128_info.page_bytes DSV4PagedBufferInfo.from_buffers(): page_bytes = buffers[0][0].numel() * element_size()
4-D 和 2-D 都正确 → V4 不会踩坑

V4.1 low-ratio（旧代码）

C1/C2 + indexer 是单独一段手写逻辑：

item_bytes=buffers[0].shape[1] * buffers[0].element_size() 4-D: shape[1] = S S * itemsize ≠ S * row_bytes
C1 KV: 128 × 1 B = 128（应为 128 × 320 = 40960）
// 另外两个 V4 没有的触发条件 1. V4 没有 C1/C2 low-ratio 池，走的是 SWA/C4/C128 各自的 entry 2. V4 SWA 是 单行页；V4.1 C1 indexer 有 I=2，需要把两个 native page 折成一个 full page
修复与结果

把“一个 full page”作为唯一单位

4-D indexer 折成 S 槽；item_bytes 取 full-page 字节；V4 路径不动，GPU 2-D 路径不动。

几何

page = buffer[: full_pages * I] if page.ndim == 4: return page.reshape( full_pages, S, *page.shape[2:]) return page.view(torch.uint8).reshape( full_pages, -1)

字节

def _dsv4_full_page_bytes(buffers): return (buffers[0][0].numel() * buffers[0].element_size())

V4 / GPU

路径不动：V4 继续用 page_bytes，GPU 2-D 继续走原来的 view(uint8)。

V4.1 low-ratio

C1/C2 和 indexer 统一按 full page 算；indexer 先折 I 个 native page。

DSpark
