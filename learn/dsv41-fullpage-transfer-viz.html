一个 full page 是怎么从 device 搬到 host 的？

页号是同一个 p（128 个 token），但底下是 4 套几何不同的池：SWA、C1/C2、indexer K、indexer scale。一次备份 = 保持同一个 host 页槽，按池拆成多次页对齐传输。

一个 full page = 128 个 token

先只记页号 p：它是 radix tree 匹配和 host 池分配的单位。下面的所有池，都是这一页的不同视图。

一次调用可以携带多个 full page；不足一页的尾部不缓存、不传输。

① 页号相同

full page p 是唯一身份。SWA、C1/C2、indexer 都用这个页号，host 侧也只分配一个页槽 p。

② 物理几何不同

C1 一页 128 槽，C2 一页 64 槽；indexer 的设备 native page 是 64 槽，但 host 行按 full page 组织，C1 的 2 个 native page 在设备上连续，传输时按 128 槽一次搬。

③ 按池、按层传输

D2H 备份 all-layer，H2D 回载 per-layer；每个池各自搬自己的一行，最后拼成同一个 host 页槽。

一句话总结

一个 full page p 的备份 =
  SWA 一行（128 槽 × 544 B）
  + C1/C2 一行（128/64 槽 × 320 B）
  + indexer K + scale 各一行（128/64 槽，按 full page 传输）
→ 全部写入 host slot p；页号不变，字节按池拆开。
